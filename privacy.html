Privacy policy

Jarvis Calendar is a private, single-owner application running on the Owner's devices. This policy covers its Google Calendar connection and this disclosure website.

Data accessed and purpose

The connection uses Google's calendar.events and calendar.calendarlist.readonly permissions. These allow access to event information and the list of calendars. Jarvis uses calendar identity, ownership and timezone to enroll the selected calendar. It uses event titles, times, availability, recurrence and provider identity information for calendar context, conflict checks, study proposals, digests and verification of exactly approved changes.

An existing read-only calendar subscription can also supply a local snapshot. Provider permissions are broader than one event. Jarvis's trusted code separately restricts writes to the selected Owner-owned calendar and the exact approved action. It does not use this connection to send invitations or add attendees.

Storage and protection

Calendar snapshots, planning settings, action parameters and receipts are stored locally in the Jarvis service directory. Owner-controlled backups may contain this local application data. OAuth client credentials and refresh tokens are stored separately from the application database. Windows protects saved tokens using current-user DPAPI. On other supported platforms, the application uses an Owner-only credential file. OAuth credentials are excluded from assistant reads, status responses and ordinary logs.

Private local pages and assistant reads require the application's Owner session. Operating-system access, local backups and model-provider settings remain under the Owner's control.

Sharing and optional model processing

Jarvis sends necessary authentication requests and approved calendar operations to Google, and reads provider state to verify results. When the Owner asks a connected assistant about the calendar, an authorized bounded snapshot may enter the conversation and the selected model provider's context. That provider processes the data according to the Owner's configured service and its policies. The public website does not receive calendar data, OAuth tokens or Jarvis passwords.

Jarvis does not sell Google Calendar data, use it for advertising, or use it to train general-purpose AI models. The Owner must select a model-provider configuration consistent with these limits. Human access to local data is limited to the Owner and people the Owner explicitly authorizes, except where disclosure is required by law.

Jarvis Calendar's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Retention, revocation and deletion

Local snapshots, settings and receipts remain until replaced or removed by the Owner. This installation has no promised automatic retention period. Pausing or disconnecting a source stops future use through that connection; it does not erase previously stored data or previously created Google events.

The Owner can revoke provider access in the Google Account's third-party connections controls. To remove stored local data, the Owner can stop Jarvis and remove the relevant service data and Owner-controlled backups. Conversation copies must also be removed through the selected assistant or provider's controls. Google events remain in Google Calendar until the Owner removes them there. Reconcile uncertain actions before removing credentials needed to verify their outcome.

This website and contact

The disclosure website is hosted by GitHub Pages. It has no forms, analytics scripts, advertising or application login. GitHub may process ordinary request information under its privacy statement.

For questions or deletion assistance, contact the application's developer and Owner at the support email shown on the Google consent screen. Never post credentials or calendar information publicly. Changes to this policy will appear here with an updated effective date.
